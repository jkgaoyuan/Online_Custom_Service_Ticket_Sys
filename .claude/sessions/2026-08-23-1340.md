### 关键决策
- **DEC-043**: `conftest.py` 采用「全局标志 + TRUNCATE + engine.dispose()」方案解决 pytest-asyncio event_loop 绑定冲突
  - **原因**: pytest-asyncio 0.21 为每个测试新建/销毁 event_loop，SQLAlchemy async engine 的连接池缓存了旧 loop 的连接，导致后续测试复用时抛出 `RuntimeError: Event loop is closed` 或 `another operation is in progress`
  - **方案 A 细节**: 全局 `_db_initialized` 标志确保整个测试进程只执行一次 `drop_all + create_all`；每个测试后 `TRUNCATE` 清数据；最后 `engine.dispose()` 强制关闭连接池，使下一个测试绑定到全新 event_loop
  - **影响范围**: `backend/tests/conftest.py`
  - **回滚条件**: 升级 pytest-asyncio 到支持 session-scoped event_loop 的版本后，可恢复更优雅的 session fixture 方案
